# 同源请求执行许可设计

状态：设计待确认，尚未实现。基于部分修复提交 3e573774195a2881f0d6841c6d59cda3f3d8057d。

## 目标和已确认范围

用户选择稳妥方案，允许增加锁，在 codex/fix-origin-pacing 分支继续提交和 push。
本设计解决 robots、普通 HTTP 和浏览器资源请求在同一 origin 上的实际发送间隔问题。
保持现有登录、验证码、robots、HTTP 401/403/429、来源批准和任务租约保护。
不增加真实来源采集、PR、合并、部署或付费服务。

成功标准：后一个读取只有在前一个读取已明确结束、且所需冷却时间已过去后才可开始。
新 robots 延迟对之后的同源读取生效；不同 origin 不共享执行锁。

## 选择与代价

采用 SQLite 中持久化的“每 origin 一个执行许可”，覆盖真实网络请求及结束确认。
不继续依赖未来时间戳排队；单纯加大间隔或重新检查时隙都不能处理任意进程暂停。
不选择全站一个锁，因为它会阻塞互不相关的网站。

这是有意更保守的调度：同源请求串行，间隔从读取结束后计算，而不是从发送前计算。
吞吐量会降低，但容易审计且不会让慢请求或慢 API 挤入其他请求的时隙。

重要恢复取舍：超时不等于旧工作进程已停止。无法确认停止时隔离该 origin，不能自动
清锁放行。这样保证安全，但不承诺所有崩溃都能自动恢复。用户确认本设计时需接受此点。

## 状态与持久化

新增迁移保留现有 origin_request_pacing 中尚未过去的预约时间，作为初始不可早于时间。
增加持久化执行状态，包括 origin、不可预测许可 token、单调 generation、owner 类型、
关联任务与租约标识、状态、deadline、cooldown_until、最近学习的 robots 延迟及其版本。
状态为 FREE、HELD、COOLDOWN、QUARANTINED。token 不出现在普通任务列表和日志中。

- FREE/到期 COOLDOWN：在短 SQLite 原子写事务内取得 HELD，返回唯一 token+generation。
- HELD：只有该 token/generation 可以完成、取消或报告屏障；同源其他请求不能发送。
- 明确完成：原子记录结束时间和延迟，转为 COOLDOWN。
- deadline 过去、服务重启遇到 HELD、完成结果不确定：转为 QUARANTINED，不能发送新请求。
- 恢复：确认原 owner 及其浏览器上下文/网络请求已停止后，由有权限的恢复操作记录原因，
  设定从恢复确认起计算的完整冷却期。仅凭时间流逝、任务 lease 过期或 token 变化不释放。

保留最近一次已完成的 token/generation 及终态，支持重复完成返回同一结果。旧 token
不得改变新许可，也不得重新打开已结束请求。未来若要自动恢复，必须先建立可验证的
进程停止机制；本轮不引入跨主机进程管理或用不可信 PID 作为停止证明。

## 安全不变量

1. 同一标准化 origin 至多一个 HELD/QUARANTINED owner；其他 origin 独立。
2. SQLite 写事务只保护状态更新，不在事务中睡眠或等待网络。
3. 许可从取得到明确完成覆盖所有真实读取，包括 robots、重定向各跳和浏览器资源。
4. 不能因超时、服务重启或租约过期而让旧请求与新请求同时取得发送资格。
5. 完成/取消必须以 token+generation 核验且幂等；旧 callback 无法释放新锁。
6. 发出资源前仍验证来源批准、配置版本、任务租约、请求 URL 和 robots 规则。
7. 所需间隔至少为生产下限、相邻来源间隔以及当前已知同源 robots 延迟的最大值。
8. 取消确认只允许在网络操作未开始，或所有相关网络操作已终止后发出。

## robots 与普通 HTTP 流程

普通 HTTP 获取执行许可，等待已有冷却结束，重新验证来源/地址规则，然后发出请求。
响应体读取或显式关闭、错误和重定向清理都必须在许可结束前完成。
保留当前最大响应体和请求超时限制，HTTP 重定向每跳重新遵守冷却与许可。

robots 检查也使用该许可。读取并解析成功后，在释放许可之前更新 origin 的共享延迟。
之后的请求因此无法在“解析结果已知道但延迟尚未发布”的空隙中抢先发送。
浏览器任务保留自身延迟快照，但 origin 共享状态是调度的权威来源。
本轮共享 robots 延迟只上调，避免规则刷新降低等待时间时影响在途请求；降低延迟需
明确、无在途请求的策略刷新操作，不自动因单次较小值回退。

## 浏览器协议

用执行许可协议替代将来时隙的 /pace 语义；旧工作进程与新服务端必须版本握手。
不兼容工作进程失败关闭，不能保留绕过许可的新旧协议混用通路。

1. worker 提交任务租约、GET/HEAD URL 和请求 ID，请求开始读取。
2. 服务端确认身份、来源、URL 后执行受许可保护的 robots 检查，并发布新延迟。
3. 请求取得用于资源读取的许可；若有队列或冷却，只返回受限等待信息，不允许先发送。
4. worker 在真正 route.fetch 前核验相同许可和当前任务/来源；过期则不发送。
5. route.fetch 保持禁止自动重定向。读取完成并清理响应后，worker 确认该许可结束。
6. 屏障会继续停用来源；普通运行失败仍保持任务级失败分类。

即使 worker 在最后核验后长时间暂停，许可仍由它占用。deadline 只使 origin 隔离，
不会把许可转给另一个 worker，因此它晚到的请求不会与新许可同时获准发送。
等待超出剩余任务预算时提前失败；不能通过不断续期延长原任务租约。

本地运行时 API 单次等待和网络操作有明确超时；超时后取消任务、尝试终止其浏览器
上下文。确认终止才能释放，否则隔离。等待者可有界重试或返回忙碌，但不能无限占用
请求线程。不同 origin 不因一个隔离来源而停摆。

## 故障处理与可见性

服务重启先把遗留 HELD 标为隔离。不会凭重启推断外部浏览器也已停止。
来源撤销、任务终止不直接清掉在途许可；先阻止新操作并完成 owner 终止流程。
完成通知丢失时 worker 可幂等重试；服务端不确定时保持隔离。
记录 permit generation、来源/任务 ID、状态、隔离原因和恢复事件，不记录许可密钥。
提供管理员可见的隔离状态和明确恢复步骤，避免把“安全暂停”误报成完成。

## 测试与验收

- SQLite：同源并发互斥、标准化默认端口、不同 origin、重启恢复、迁移旧预约、锁竞争。
- token：重复完成幂等、旧 generation 无法释放新 owner、取消与完成竞争。
- robots：先发布新延迟再放行；其他来源的 robots/HTTP/浏览器请求不能抢跑。
- 浏览器：在取得许可后、最终核验后人工暂停；超过 deadline 仍不得给同源新请求许可。
- 故障：worker 崩溃、完成通知丢失、服务重启、浏览器关闭失败、租约过期都失败关闭。
- 真实 fixture 请求时间：文件 SQLite、多来源、多进程、HTTP 与浏览器混合，验证请求结束
  到下一请求开始的冷却下限。仅检查预约数字不能替代真实派发测试。
- 回归：来源屏障、策略撤销、凭据隔离、任务结果与前端完整测试。

当前云环境仍有 Java 依赖审批取消和浏览器本地 socket 限制。不得重试被取消命令或绕过
限制。能执行的静态/SQLite/协议检查与未执行的 Java/浏览器验收分别记录；不得声称完整通过。
